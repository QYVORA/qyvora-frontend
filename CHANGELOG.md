# Changelog

All notable changes to `qyvora-frontend` are documented here.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **PWA rebuilt for the whole site** — `manifest.webmanifest` now covers `/` (scope + `start_url`) instead of `/dashboard/`, with real PNG icons (`192`/`512` `any` + `maskable`, `apple-touch-icon`) generated by `npm run icons:pwa`, `display_override`, and app shortcuts for Dashboard, Learn and the terminal simulator
- Service worker (`public/sw.js`) rewritten: app-shell precache (shell, offline page, manifest, fonts, icons), network-first navigations with a 4s timeout that fall back to the cached shell and then to a new branded `public/offline.html`, stale-while-revalidate for same-origin assets, and `/api` + `/uploads` never cached
- `vite-plugin-sw-precache` — rewrites `CACHE_VERSION` and `BUILD_ASSETS` in the emitted `dist/sw.js`, so the hashed entry graph (entry chunk, vendor imports, CSS) is precached per build; without it the first page load's JS is fetched before the worker takes control and the app cannot boot offline
- `vite-plugin-webp-conversion` gained an `exclude` option — PWA manifest icons stay PNG (no WebP twins in the deploy)
- `PwaStatus` (`shared/components/layout`) — one fixed column hosting every passive PWA notice: "Update ready" reload card, `// OFFLINE` strip and the install banner; mounted in both `PublicShell` and `AppShell`
- Service-worker update flow: the worker no longer self-activates, a waiting build is announced in-app, and accepting it posts `SKIP_WAITING` and reloads on `controllerchange`; updates also re-check when a tab regains focus
- iOS Safari install instructions in the install banner (it never fires `beforeinstallprompt`), and `navigator.storage.persist()` on accepted installs
- 15 unit tests for the PWA service (`core/services/__tests__/pwa.test.ts`)

### Changed
- PWA service moved from `features/student/services/pwa.ts` to `core/services/pwa.ts` (whole-site scope) with React bindings in `core/hooks/usePWA.ts` (`useInstallPrompt`, `useServiceWorkerUpdate`, `useOnlineStatus`) via `useSyncExternalStore`
- Service worker registration moved from `AppShell` to the app entry (`app/main.tsx`) and is skipped in dev unless `VITE_ENABLE_SW_IN_DEV=true` — a worker caching Vite's module graph breaks HMR
- `InstallBanner` moved to `shared/components/layout/`, rebuilt on `useInstallPrompt` (it previously polled a module-level flag every 2s from the dashboard and only reacted on unrelated re-renders)
- Removed the duplicate "Install QYVORA" card from the dashboard overview — the single popup-managed banner owns that prompt now
- Push notification click handling focuses or navigates an existing tab of the same origin instead of blindly opening a window
- Fixed theme bootstrap: extracted the inline first-paint theme script into `public/theme-init.js` and referenced it with `<script src>`, because the deployed CSP (`script-src 'self'`) was blocking inline execution on every page load

- Admin dashboard

- Error boundary with scope-based error capture

- XSS protection headers
